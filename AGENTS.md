# AGENTS.md

SAHAYAK — elderly-care management app. TanStack Start (file-based routes) + React 19 + Vite + Tailwind 4 + shadcn/ui. Supabase (Postgres + Auth + RLS) is the **only** backend; there is no custom API layer.

## Commands

- `npm install` — package manager is **npm** (`package-lock.json`). `bun.lock`/`bunfig.toml` are template leftovers; bun is not installed here.
- `npm run dev` / `npm run build` / `npm run preview` — Vite.
- `npx tsc --noEmit` — typecheck. There is **no** `typecheck` or `test` script; there are no tests and no CI workflows. Typecheck + lint is the whole verification loop.
- `npm run lint` — ESLint with Prettier rules folded in (`eslint-plugin-prettier`), so lint enforces formatting too.
- `npm run format` — `prettier --write .` (printWidth 100, double quotes, trailing commas).

**Windows line-ending trap:** this machine has `core.autocrlf=true` and no `.gitattributes`, so the working tree is CRLF while Prettier enforces LF — a fresh checkout fails `npm run lint` with ~12k `Delete ␍ prettier/prettier` errors. Run `npm run format` first (git normalizes on commit, so no spurious diff), then lint. Remaining lint errors after that are real; one pre-existing one is `prefer-const` in `src/integrations/supabase/previewAuthStorage.ts:38`.

## Do not hand-edit (generated)

- `src/routeTree.gen.ts` — regenerated by the TanStack Router plugin.
- `src/integrations/supabase/client.ts` and `client.server.ts` — generated Supabase clients.
- `src/integrations/supabase/types.ts` — the `Database` type. **You do update this by hand when the schema changes**: recent migrations were committed together with a matching `types.ts` edit. Keep them in sync.
- `drizzle/schema.ts` — intentionally blank (`do not edit`); the schema is _not_ modeled in Drizzle. Migrations are hand-written raw SQL.
- `vite.config.ts` — plugins (tanstackStart, react, tailwind, tsConfigPaths, nitro, `@` alias, VITE_* env injection, sandbox port detection) come from `@lovable.dev/vite-tanstack-config`. **Never add plugins manually — duplicates break the app.** Extend via `defineConfig({ vite: { ... } })` instead.

## Routing

- File-based routing lives entirely in `src/routes/`. Read `src/routes/README.md` before adding routes: bare `$` for params, `$` splat, `_` layout prefix, `__root` is the only root layout. Do not create `src/pages/`, `app/`, or other Next.js/Remix conventions.
- Staff pages go under `src/routes/_shell/`; `src/routes/_shell/route.tsx` gates them in `beforeLoad` (session check + role check — `family`-only users are redirected to `/family`).
- New staff pages must also get an entry in `src/lib/navigation.ts` (`navGroups`, with `roles`) or they won't appear in the sidebar.
- The Reports page was deliberately removed — do not reintroduce it (`roadmap.md`: "removed modules stay removed").

## Data access & security

- All queries are client-side Supabase via TanStack Query, in `src/features/<domain>/queries.ts`. Security is enforced by **RLS policies in SQL**, not in app code — every new table needs policies/grants (see `drizzle/migrations/0005_staff_only_guard.sql` for the current restrictive staff/family guard pattern).
- Role bootstrap happens through RPCs: `supabase.rpc("ensure_staff_account")` / `ensure_family_account` (see `src/hooks/use-auth.tsx`, `src/routes/auth.tsx`).
- SSR plumbing: `src/server.ts` is the TanStack server entry (500-page wrapper for h3-swallowed errors — keep it); `src/start.ts` defines CSRF + `attachSupabaseAuth` middleware — deleting it silently drops CSRF protection.
- `client.server.ts` uses the service-role key and must be imported dynamically inside handlers: route files and `*.functions.ts` ship to the client bundle.

## Database migrations

- **New migrations go in `drizzle/migrations/`** as `NNNN_description.sql`, with a matching entry appended to `drizzle/migrations/meta/_journal.json` and a `NNNN_snapshot.json` (id/prevId chain; snapshots are intentionally empty stubs).
- `supabase/migrations/` is the older Lovable history, untouched since Aug 2026 — don't add files there.
- Migrations are a **record only**: they're applied manually in the Supabase dashboard (no migrate script runs anywhere). Write SQL that is safe/idempotent to paste into an existing database.
- Note `drizzle.config.ts` expects `LOVABLE_DB_MIGRATION_URL`, which is not in `.env` — `drizzle-kit` DB commands won't work locally as-is.

## Environment

- `.env` (gitignored) must define `VITE_SUPABASE_URL` + `VITE_SUPABASE_PUBLISHABLE_KEY` (plus non-`VITE_` copies for the SSR fallback). The Supabase client throws at startup if they're missing — "Connect Supabase in Lovable Cloud."
- Project structure: `src/routes` (pages), `src/features/<domain>/queries.ts` (data), `src/components/{ui,layout,common,<domain>}` (shadcn base in `ui/`), `src/lib` (shared helpers), `src/integrations/supabase` (generated clients/types).
